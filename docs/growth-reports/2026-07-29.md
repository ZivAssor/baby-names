### The structural finding: this is a one-page site to Google

Over the last **90 days**:

| Segment | URLs with impressions | Impressions |
| --- | --- | --- |
| Homepage | 1 | **147,600** (99.8%) |
| All other non-`/name/` pages | 23 | ~110 |
| `/name/` pages | 131 | ~200 (28d) |

`/rare` took 18 impressions in 90 days. `/top-names`, `/trending`, `/years`,
`/stories` took zero. This is not a crawlability problem - I checked
`robots.ts` (clean), the sitemap (correct), and the link graph (Header, Footer
and GenderHub all link the hubs in server-rendered HTML, and `/names` ->
`/names/[letter]` -> `/name/[name]` is intact with `dynamicParams = true`, so
the ~14k non-prerendered names do not 404). The hub pages are simply too thin
to be chosen over the homepage.

### `/name/` long-tail indexing

131 URLs have picked up at least one impression; ~200 impressions in 28 days.
They only entered the sitemap on 2026-07-27, so this is early and on track, not
a concern. Worth watching: the few name queries GSC will show unanonymised rank
poorly for their own exact name (`אלטי` position 25, `אנווה` 10, `איידל` 9) -

### Striking distance

**Zero** queries sit in the classic 8-20 band with meaningful impressions.
Everything ranks 2-6. The opportunity here is not rank, it is CTR and page
selection.

## What I changed

### Rebuilt `/rare` to own the rare-names browse cluster

The rare-name demand splits cleanly into two intents:

| Intent | Impressions (14d) | Position | Served by |
| --- | --- | --- | --- |
| "how rare is **my** name" (`כמה השם שלי נדיר` 164i, `כמה נדיר השם שלי` 66i, ...) | ~370 | **2.5 - 3.5** | Homepage, correctly |
| "the rare names **list**" (`שמות נדירים` 83i, `השמות הכי נדירים בישראל` 13i, `השמות הנדירים` 22i, ...) | ~150 | **7.3 - 8.0** | Homepage, badly |

That gap is the tell: the browse queries rank ~5 positions worse than the
personal ones because Google was serving the homepage for a query it does not
fit, while the page that *does* fit was 60 names and five sentences.

Changes (`app/rare/page.tsx`, +155/-23):

- Title/description rewritten through `pageMetadata()` to match the browse
  phrasings (`שמות נדירים בישראל - השמות הכי נדירים לבנים ולבנות`). Description
  tightened 168 -> 123 chars so the hook survives SERP truncation.
- Three sectioned lists with their own headings, replacing the single flat 60:
  the names at the rarity floor, plus `שמות נדירים לבנות` and
  `שמות נדירים לבנים` (36 each) - the gender phrasings had no heading anywhere
  on the site before.
- A four-question FAQ block with `FAQPage` structured data, answering the real
  query phrasings. One question is the suppression explainer, which is both
  honest and the kind of thing AI assistants cite.
- `BreadcrumbList` structured data and a `ShareButton`, matching `/top-names`.
- Internal links out to `/top-names` and `/names` added.

**Numbers are derived, not written by hand.** The page now quotes 19,882 total
names, 6,222 that meet the rare definition, and 755 that have exactly 5 bearers
- all computed at build time from the generated data and verified in the
rendered HTML.

Two honesty fixes made along the way:

- The headline list is now filtered to names *at* the floor value, so the claim
  "5 bearers each" is true of every name shown, not just the first few.
- Pre-existing copy said `פחות מ-30` but `rareNames()` keeps `totalAll <= 30`.
  Corrected to `עד 30` in the body, the metadata and the FAQ.

Suppression contract checked: `totalAll` comes from the CBS `t` column and is
never `-1` (verified - minimum across all 19,882 entries is 5), so no suppressed
value can surface as a count here. The existing `rareNames()` recency filter
correctly treats a suppressed year as "in use" (`c[i] !== 0` is true for `-1`).
No new statistic was introduced.

Internal linking needed no change: the homepage already links `/rare` with the
anchor text `שמות נדירים`, which is exactly the target query.

### What I deliberately did not do

**I did not touch the homepage title or meta description.** The homepage has
the biggest raw CTR gap on the site (4.2% CTR at average position 3.9, roughly
half of what that position should yield; `השמות של ישראל` gets 1.3% CTR at
position 2.4). But commit `ecb849b` rewrote exactly this on 2026-07-28, *after*
my measurement window closes. Changing it again now would discard the only
chance to measure whether that rewrite worked. It should be measured next run.

**No name story shipped.** Story work requires a dated, 2+-source verified
trigger, and I would rather ship nothing than a maybe. I did run the spike scan
so the next run can start from research instead of mining - see below.

## Expected impact

Modest and specific. The browse cluster is ~150 impressions/14d at position
~7.5. If the rebuilt page takes those queries to the top 3, that is roughly
+100-200 clicks/month, plus whatever the gender headings pick up from phrasings
we previously had no page for. The larger value is the test: if a deepened hub
page can win its query away from the homepage, the same play applies to
`/top-names`, `/trending` and `/years`, which are all currently at zero.
