## 2. Actions taken

### A. Name-page titles now lead with the name and the number

**Why.** The old title was `כמה אנשים נושאים את השם <name>?`. That is the
*homepage's* winning query phrasing, and it buries the name ~24 characters in.
But name pages do not rank for that phrasing - the queries that actually reach
them are overwhelmingly the bare name:

| Query shape | Queries | Impressions |
| --- | ---: | ---: |
| bare name | 206 | 705 |
| `<name> שם` | 45 | 136 |
| `השם <name>` | 31 | 63 |
| other | 48 | 324 |

In an RTL SERP the leading words are what the searcher scans and what Google
bolds. So the name moves to the front, and the count - the answer they came for -
goes in the title instead of only the body.

```
before: כמה אנשים נושאים את השם אלינור? | דשבורד השמות של ישראל
after:  אלינור - 5,524 אנשים בישראל נושאים את השם | דשבורד השמות של ישראל
```

The description was rewritten the same way (name first) and now carries the
gender character, which the old one omitted:

```
before: 5,524 תושבי ישראל נושאים את השם אלינור · שנת השיא: 1981 · גרפים ונתונים מלאים מ-1949 עד היום, על בסיס נתוני הלמ״ס.
after:  אלינור: 5,524 תושבי ישראל נושאים את השם · שם בנות מובהק · שנת השיא 1981 · גרפים ומגמות לפי שנה ומגדר, נתוני הלמ״ס 1949-2024.
```

**Suppression check** (per CLAUDE.md, done before shipping): the only number
either string prints is `totalAll`, which is the CBS `t` column. Verified
against `data/generated/name-directory.json` across all 19,882 entries - min 5,
max 130,529, zero `-1` values and zero zeros, because CBS drops the row entirely
below 5. It is safe to print exactly. `genderCharacter()` derives from
`totalM`/`totalF`, which are sums of per-series `t` totals, also never
suppressed. `peakYear` is a year label, not a count - the suppression-sensitive
`peakCount` is deliberately **not** printed. No yearly counts appear in either
string.

Both go through `pageMetadata()`, so the full openGraph block is preserved.

### B. The 28 name stories are no longer orphaned

`/stories/<slug>` was reachable from exactly one place: the `/stories` index,
which averages position 41.4. Meanwhile 28 hand-researched, source-verified
stories sit on names whose `/name/` pages now rank in the top 10.

Each name page with a matching story now renders a callout with the story's
hook and a link to it. The reverse link (story to name page) already existed;
this closes the loop. Verified all 28 slugs equal their `name` field, so all 28
get linked.

### C. No name-story work this run

I ran no new spike scan. The story pipeline in CLAUDE.md requires a dated,
2+-source verified cultural trigger, and with the `/name/` CTR finding sitting
in front of me at 3,444 impressions and growing, a story would have been the
lower-value use of the run. The existing 28 stories getting internal links is
worth more this week than a 29th would have been.

## 4. Expected impact

The name-page change is the one with real upside: 3,444 impressions in 14 days,
980 pages at position <=10, currently 2.35% CTR. Positions 4-10 in Hebrew search
typically return somewhere in the 3-8% range, so closing even half the gap is
roughly +50 to +100 clicks per 14 days at *current* impressions - and impressions
went from ~0 to 3,444 in about two weeks, so the base is still growing fast.

Caveat I want to be honest about: this is a bet, not a measurement. I cannot
A/B test titles, the change is uniform across 6,000 pages, and Google will take
one to three weeks to recrawl and reflect it. **Next run should compare
`/name/` CTR against this run's 2.35% baseline** - if it has not moved by
2026-08-24, the hypothesis was wrong and the title should be reconsidered
rather than iterated on.

The story-linking change is small and safe; expect it to show up as the first
non-zero clicks on `/stories/` pages rather than as a traffic event.

## Owner decisions needed

1. **What caused the 2026-07-26 burst?** GSC gives queries, not referrers. The
   phrasing (`כמה בנים וכמה בנות נקראו בשם שלכם`,
   `רוצים לדעת אם השם שלכם נדיר`) strongly suggests a media mention or a widely
   shared post around 07-25/07-26. If you know the source, it is worth recording -
   it is the second such burst the site has seen, and knowing what kind of
   placement triggers one is more valuable than any SEO fix in this report.

2. **`דשבורד` vs `אתר` / `מאגר` / `מחשבון` in the site name.** A cluster of
   queries using vocabulary the site does not use is surging, all new or
   near-new this window: `אתר שמות` (1,340 impr, 1.27% CTR at pos 4.4),
   `מאגר שמות` (71), `מחשבון שמות` (108), `מאגר השמות` (52),
   `מאגר שמות בישראל` (40). Meanwhile the brand queries that *do* contain
   `דשבורד` convert at 73-93% CTR. Changing `SITE_NAME` would trade a very
   strong brand signal for a broader-match one, and that is a brand decision,
   not an SEO one - so I did not touch it. If you want it explored, a middle
   path exists (leave `SITE_NAME` alone, work the alternative vocabulary into
   `SITE_DESCRIPTION` and homepage body copy).

3. **`השמות של ישראל` at 2,240 impressions and 1.52% CTR, position 2.2.** That
   is anomalously low for the position, and the homepage title contains the
   phrase almost verbatim. My best guess is mixed intent - the phrase also
   reads as a reference to something else - but I could not confirm that from
   GSC, and I was not willing to rewrite the homepage title on a guess. Flagging
   rather than acting.

4. **Core Web Vitals went unmeasured this run** (PSI quota, HTTP 429). Per the
   brief, the INP validation in Search Console runs until ~2026-08-25 and should
   not be re-diagnosed before then, so this is a gap in the record rather than
   an open risk. Next run should retry.
